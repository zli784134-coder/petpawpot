# 给工厂的补充测试需求单

> 版本 1.0 · 2026-08-19 · 提出方:PetPawPot
> 背景:已收到 JP6001 / JP6011 温升试验数据。该数据用于安规验证是完整的,
> 但**无法回答两个业务必需的问题**,需补一组测试。

## 为什么要补

现有报告的七个热电偶全部贴在机器上(桶壁/发热盘/空间桶/NTC/环境/大身/
铝桶外部),且没有任何质量记录。因此:

| 我们需要知道 | 现有数据能否回答 |
|---|---|
| 食物中心温度达到多少、维持多久 | ❌ 无食物测点 |
| 生食材煮熟后重量变成多少(得率) | ❌ 无质量记录 |

这两项直接影响我们的营养计算与食品安全表述,**必须实测,不能估算**。

好消息是:**两件事可以在同一次测试里一起完成**,不增加多少工作量。

## 一、需要补的测点

在现有布点基础上,**增加一根食物中心热电偶**:

- 位置:桶内食物堆的**几何中心**,探针尖端距桶壁与桶底均 ≥ 2 cm
- 若食物量少无法居中,记录实际插入位置并拍照
- 采样率与现有一致(1 秒)

**布点问题已于 2026-08-19 澄清**(工厂说明 + 现场照片):
- 铝桶外部 = 接近桶底(紧邻发热盘)
- 桶内壁 = 比较靠上(为避免搅拌桨刮到线)

这解释了"外部比内壁热"的现象,但也说明:**内壁那根测到的是食物堆上方的桶壁
温度,不是食物温度**。因此食物中心探针仍是必需的,不能用现有内壁数据替代。

## 二、称重法得率测试

### ⚠️ 先确认:这部分数据可能已经存在

2026-08-15 14:17 的现场照片显示,测试前已用电子秤称过食材(读数 501.4 g)。
**说明称重环节实际发生过,只是没写进报告。**

请先回答三个问题,若答案齐全,下面的完整流程就不必重做:

1. 501.4 g 是**净重**(已去皮)还是**含容器毛重**?
2. 程序结束后**是否也称了熟重**?数值是多少?
3. 该次投料的**食材构成与各自克数**(照片里至少有鸡腿肉和一块深色肉)?

若熟重已有记录,请连同历史测试的称重记录一并补交 —— 那样我们立刻就能算出
得率,不需要新开一轮测试。

### 若需重做,按以下流程

### 流程(每个样本)

```
1. 称空桶重                        → 记 A (g)
2. 放入生食材,称总重              → 记 B (g)    生食材净重 = B - A
3. 加水(如程序需要),称总重      → 记 C (g)    加水量 = C - B
4. 运行指定程序至自动结束
5. 静置 10 分钟后称总重            → 记 D (g)
6. 取出食物称净重                  → 记 E (g)
```

**得率 = E ÷ (B - A)**

### 样本量

- 每种食材 × 每个程序 **各做 2 次**,取平均
- 生食材投料量按该机型**标称满载的 70%**,并记录实际克数

## 四、其他需要确认的问题

1. **JP6011 的测点说明** —— 该份数据没有附通道与位置的对应表
2. **各程序的设计时长** —— 实测:湿粮 ~50 分钟、快煮 ~32 分钟、精煮 ~73 分钟、
   肉松 60 分钟整、生骨肉 ~14 分钟(不加热)、清洗 ~26 分钟。
   请确认这些是**程序跑完的自然时长**,还是测试中被手动停止
3. **生骨肉档确认不加热** —— 实测全程 22–30 °C,请确认该档设计上就不加热
4. **已有称重记录是否可补交** —— 见第二节开头的三个问题
5. **两机型是否都会销售** —— JP6011 峰值 168 °C 明显高于 JP6001,
   若两款并行销售,配方与说明书的程序参数需分别标注

## 五、这些数据我们会怎么用

- **得率** → 修正营养引擎的熟成换算,直接影响给用户的克数建议
- **中心温度曲线** → 判断食品安全表述能否成立;在拿到数据前,我们不会在
  网站上做任何关于杀菌或中心温度的声称

得率数据一旦落地,任何修改都会先经过我们的犬猫营养复审流程,再上线。
